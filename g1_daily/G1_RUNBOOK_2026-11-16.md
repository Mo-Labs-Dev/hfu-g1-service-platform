## 2. What exists now (built 15–16 Nov 2026)

### 2.1 Operator joystick (app + teleop server)
- Server: `hfu-g1-service-platform-main/robot/teleop/` (`teleop_controller.py`, `teleop_api.py`, `motion_backends.py`), runner `scripts/run_teleop_server.py`, docs `docs/architecture/TELEOP_JOYSTICK.md`.
- The server is the **single owner of locomotion commands**: PIN lease (one operator), dead-man 0.3 s, `SetVelocity` duration 0.4 s, speed clamps (fwd 0.25 / back 0.15 / side 0.20 m/s, yaw 0.30 rad/s), accel limits, moves only in FSM 500, latched software E-stop, any RPC error → E-stop.
- **Validated on the robot (harness):** forward/backward/sideways/turning in correct directions; release-stick stop.
- **Finding:** the G1 does not walk below ~0.15 m/s (at 0.10 m/s it only shifts weight). This explains the earlier "SetVelocity only slight body movement" issue from the FAST-LIO handover.
- FSM is read via raw RPC api 7001 (installed SDK has no `GetFsmId`). Service name `sport`.
- App: long-press the HFU logo → operator screen → PIN. Robot-mode buttons Damp (1) → Stand up (4) → Walking mode (500) with server-side order checks. ZeroTorque intentionally not offered.
- API: `POST /api/teleop/unlock|lock|stop|estop|estop/reset|mode`, WebSocket `/api/teleop/ws?token=`.

### 2.2 Robot Show & voice gestures (arm actions)
- Arm Action service rebuilt for the old SDK: service `arm`, version `1.0.0.14`, api 7106 execute / 7107 list, `{"data": id}`.
- **Robot Show** (home tile, no PIN, on by default; disable with `--no-robot-show`): wave, friendly wave, clap, heart, flying kiss.
- **Talk to G1 voice commands** additionally allow **handshake** and **high five** (EN + DE phrases, max 9 words). Hug never.
- Rules: FSM 500, standing still, no E-stop, one at a time, 4 s rest; sustained gestures are released with id 99.

### 2.3 Natural voice (Piper)
- `hfu_voice/g1_voice_bridge.py` replaces `/ros2_ws/g1_speech_bridge.py` (same port 8766, same `/speak`). Old file kept for rollback.
- Voices in `hfu_voice/voices/`: `de_DE-thorsten-medium` (DE, male), `en_US-ryan-medium` (EN, male). `pip install piper-tts` done in the container.
- Audio goes to the G1 speaker via voice service api 1003 `PlayStream`, rebuilt for the old SDK (one request with JSON param + 16 kHz PCM).
- Extra API: `lang`, `queue`, `ends_in_ms` in the answer, `GET /status`, `POST /stop`.

### 2.4 Backend changes (`hfu-g1-studio/services/api/app`, `.bak` copies kept)
- `services/interaction_service.py` + `api/interaction.py`: spoken-style answers; optional `language` ("en"/"de") forces answer language and voice; returns `speech_ends_in_ms`.
- `main.py`: automatic camera welcome **off** by default (`G1_AUTO_WELCOME=1` to enable).

### 2.5 App (G1 Remote, Android Studio on the Mac)
- New/changed: `G1TeleopClient.kt`, `VirtualJoystick.kt`, `OperatorJoystick.kt`, `VisitorRobotShow.kt`, `TalkToG1Ui.kt`, `MainActivity.kt`, OkHttp 4.12 in `build.gradle.kts`.
- Talk to G1: redesigned (white/green), language switch EN/DE inside the screen.

## 3. Safety rules (unchanged principle: physical stop first)
- Physical E-stop / Unitree remote in hand during every robot test.
- The runbook rule "velocity locked until independent stop/watchdog validated" is addressed by the teleop server's dead-man/watchdog; document stop tests (release stick, STOP, Wi-Fi off, server kill) in the thesis log and inform the supervisor.
- Only one motion sender at a time (do not run G1Pilot's LocoClient node or G1 Studio FSM buttons while the teleop server drives). The backend is started **without** `G1_ALLOW_POSTURE/LOCOMOTION_COMMANDS` for this reason.
- Autonomous walking stays disabled until localization, footprint/collision geometry and the route are validated (see §4).

## 4. Autonomous walking — plan

Goal: *Visitor asks for the coffee machine → G1 plans a safe route → guides → announces arrival.*

```
Session 03 PCD ─► (A) 2D map ─► Nav2 map_server
Livox MID-360 ─► FAST-LIO odometry ─► (B) localization vs. PCD ─► map→odom TF
Nav2 planner + controller (live LiDAR costmap) ─► /cmd_vel
/cmd_vel ─► (D) teleop controller as motion owner (limits, watchdog, E-stop, teleop override) ─► SetVelocity
Backend guide state machine ─► NavigateToPose ─► voice announcements
```

| Step | What | Status |
|---|---|---|
| A | PCD → 2D occupancy map (`hfu_nav/pcd_to_nav2_map.py`) | **built, run on Session 03 next** |
| B | Relocalization in the saved map (ICP against Session 03 PCD; earlier offline test: fitness 0.9967, RMSE 0.067 m) | next |
| C | Named waypoints (entrance, home, coffee machine, stations) in map frame | after B |
| D | Nav2 `/cmd_vel` → teleop controller (autonomy source, teleop always overrides) | after B |
| E | Footprint/inflation for G1 incl. arms; check table + crane collisions from earlier planner test | with D |
| F | Staged tests: RViz only → harness 0.15 m/s → empty lab → with people | last |
